## Что получилось

- Bronze: customer 750 000, orders 7 500 000, lineitem 29 999 795 строк; только колонки Q18.
- Silver: 301 крупный заказ в каждой из двух учебных загрузок, всего 602 записи истории. Первая дата загрузки искусственно задана как вчера; это демонстрация, а не реально прошедшие сутки.
- Gold: 100 актуальных заказов. Все шесть полей совпали с результатом Q18.
- Q18 выполнен 18 раз на шести сочетаниях Parquet/ORC и ZSTD/SNAPPY/GZIP; во всех результат одинаковый.
- Добавление, переименование, удаление колонки и следующая вставка проверены на маленькой копии Silver.
- Ошибочная строка добавлена в настоящую Gold, прочитан старый snapshot, выполнен rollback; Gold снова точно совпала с Q18.
- Отдельный Spark 3.5.3 в Docker прочитал все три Bronze-таблицы, исполнил Q18 и проверил Gold через тот же Lakekeeper/MinIO. Видеокарта не использовалась.

## Запуск на этом компьютере

Из PowerShell в папке проекта:

```powershell
.\deploy-stack.ps1
# Пайплайн уже выполнен. Повторно run-lab.ps1 не запускай: он защищает сохранённый результат.
.\run-spark.ps1
```

Повторная Spark-проверка заменяет её собственные лог/JSON. Для хранения нескольких проверок сначала скопируй `results/spark-*` в отдельную папку.

В DBeaver выбери соединение localhost:8080, пользователь trino, пароль пустой, каталог bench:

```sql
SHOW TABLES IN bench.v3_bronze;
SELECT * FROM bench.v3_gold.large_volume_customers
ORDER BY totalprice DESC, orderdate;
SELECT load_batch, count(*) FROM bench.v3_silver.large_orders_history
GROUP BY load_batch;
```

## Воспроизведение на чистом стенде

Нужны Docker Desktop с Linux containers, PowerShell 7 и доступ к Maven/реестрам образов. Существующие контейнеры с теми же именами не пересоздаются; если это другой стенд, сначала проверь его конфигурацию. Скрипт сохраняет все volumes и не содержит очистки.

```powershell
.\deploy-stack.ps1
# В скачанном проекте уже лежат доказательства старого запуска. Сохрани их под другим именем:
Rename-Item -LiteralPath '.\results' -NewName 'results-from-submission'
.\run-lab.ps1
.\run-spark.ps1
```

Стек собирается командами docker run, не требует Docker Compose. Основные образы закреплены digest в `deploy-stack.ps1`, Spark 3.5.3 и JAR 1.7.1 заданы явно. На текущем компьютере проверен путь переиспользования существующего стенда, а не создание второго чистого стека. При новом запуске скрипт Spark скачает два JAR и проверит SHA1 Maven Central; JAR не включаются в Git.

В публичной версии конфигурации — шаблоны без паролей. Перед запуском создай папку `.local`, скопируй туда `configs/settings.example.json` под именем `settings.json` и заполни свои локальные значения. `prepare-runtime.ps1` подготовит конфигурации в `.local`, которая исключена из Git. Для уже существующего стенда значения должны совпадать с его настройками. Стенд без production-аутентификации; не выставляй порты в интернет. MinIO:9000/9001, Lakekeeper:8181, Trino:8080, PostgreSQL:5432.

## Структура

`assignment/` — исходные материалы преподавателя. `sql/` — исходный Q18 и слои. `configs/` — Trino/Spark. `run-lab.ps1` — pipeline, проверки и бенчмарк. `run-spark.ps1`, `spark/` — внешний потребитель. `results/` — исполненные SQL, query id, Trino stats, фактические строки результатов, CSV/JSON размеров и времён, история, snapshots и логи. `results/attempt-01/` хранит первую ошибку HTTP API с точкой с запятой; она исправлена.

## Измерения

Сравниваются **все три Bronze-таблицы** с одинаковыми колонками и SF5. Все шесть тестовых копий создаются из одного материализованного Bronze, чтобы источник записи был одинаковым. Формат задан в CREATE TABLE, кодек — HTTP session property `bench.compression_codec`; фактические свойства Iceberg сохранены. GZIP у ORC обозначается ZLIB.

Для Q18 сохранены три повтора, серверное `elapsedTimeMillis` и клиентское полное время HTTP-запроса. В отчёте — медиана серверного времени. Размер — сумма data-file bytes по `$files`, **не SHOW STATS**, без Iceberg-метаданных; MB = 1 000 000 байт. Кэш не сбрасывался, порядок не рандомизирован; первый повтор не называется гарантированно cold. Число файлов тоже немного меняется и может влиять на чтение. Это учебные замеры одного компьютера, не сертифицированный TPC-H score.

Краткие первоисточники по использованным API: [Trino Iceberg](https://trino.io/docs/current/connector/iceberg.html), [Lakekeeper bootstrap](https://github.com/lakekeeper/lakekeeper/blob/main/docs/docs/bootstrap.md).
